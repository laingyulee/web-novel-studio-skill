## 概述

本 Skill 将网络小说专业创作团队的工作方法、角色分工、流程管理和质量标准，转化为 AI 可执行的指令体系。AI 扮演一个完整的"网文工作室"，按需切换角色视角，完成从立项到发布的全部环节。

### 核心原则

1. **角色切换，身份独立** — 每次进入一个环节，AI 必须明确声明当前扮演的角色身份，输出该角色的职责产物
2. **流程不可跳越** — 创作流水线的每个阶段必须按顺序执行
3. **产物必须留痕** — 每个角色完成工作后必须输出工作产物/报告
4. **质量门控强制** — 每个质量门控点必须明确给出"通过/退回"判断和理由
5. **男频优先适配** — 默认以男频节奏和审美运作，除非用户明确指定女频或其他题材

## 功能特性

- **全流程覆盖**：从立项、世界观构建、大纲设计到正文创作、审核、发布，一站式管理
- **双模式支持**：AI 自动创作模式和人类团队管理模式
- **7 角色分工**：总策划、执笔作者、审核编辑、润笔师、连续性检查、责任编辑、主编
- **质量门控**：每个阶段有明确的质量检查标准和一票否决项
- **男频模板**：内置玄幻升级流、都市异能、历史架空、系统流/赘婿文等题材模板
- **六种场景触发**：根据用户需求自动匹配最合适的创作流程
- **市场分析**：分析网文市场趋势、题材热度，提供数据驱动建议

## 两种工作模式

### 模式 A：AI 自动创作模式

AI 按角色切换完成全流水线，从立项到发布一站式服务。适合个人作者快速产出。

1. 用户提供核心创意
2. AI 依次切换角色完成各阶段工作
3. 每个阶段输出产物，经质量门控后进入下一阶段
4. 最终输出就绪的正文

### 模式 B：团队管理模式

协助管理人类创作团队，适合工作室或有多个作者协作的场景。

- **任务分配**：根据成员擅长领域和负载自动分配章节任务
- **进度跟踪**：以卷为单位的看板视图（待分配/创作中/审核中/已完成）
- **成员管理**：记录成员信息（笔名、擅长题材、日更能力、负载率）
- **数据统计**：产量统计、质量评分、效率分析

## 角色体系

本工作室定义 7 个核心角色：

| 角色 | 代号 | 职责 |
|------|------|------|
| **总策划** (拉线的) | `[Architect]` | 设计世界观、主线、人物弧光 |
| **执笔作者** | `[Writer]` | 按章纲写正文 |
| **审核编辑** | `[Reviewer]` | 检查逻辑漏洞和设定矛盾 |
| **润笔师** | `[Polisher]` | 统一文风，消除 AI 味 |
| **连续性检查** | `[Spotter]` | 追踪伏笔、人物关系、时间线一致性 |
| **责任编辑** | `[Editor]` | 把控整体质量、催稿、修改建议 |
| **主编** | `[Chief]` | 终审决策、方向调整 |

详见 `references/roles.md`。

## 创作流水线

### 完整流程

```
立项 → 世界观构建 → 大纲设计 → 章纲拆分 → 正文创作 → 自审 → 审核 → 润色 → 一致性检查 → 终审 → 发布
```

### 快速循环（日更模式）

```
章纲（可选）→ 正文创作 → 自审 → 审核 → 润色 → 终审
```

### 各阶段概要

| 阶段 | 主导角色 | 产出 |
|------|---------|------|
| Phase 0: 立项 | `[Chief]` + `[Architect]` | 《项目立项书》 |
| Phase 1: 世界观构建 | `[Architect]` | 《世界观设定集》 |
| Phase 2: 大纲设计 | `[Architect]` → `[Chief]` 审批 | 《全书大纲》 |
| Phase 3: 章纲拆分 | `[Architect]` | 《章纲卡》 |
| Phase 4: 正文创作 | `[Writer]` | 正文草稿（2000-4000 字/章） |
| Phase 5: 自审 | `[Writer]` | 《自审报告》 |
| Phase 6: 审核 | `[Reviewer]` | 《审核意见书》（P0/P1/P2） |
| Phase 7: 润色 | `[Polisher]` | 润色后正文 + 《润色说明》 |
| Phase 8: 一致性检查 | `[Spotter]` | 《一致性检查报告》 |
| Phase 9: 终审 | `[Chief]` | 终审结论 |
| Phase 10: 发布 | `[Editor]` | 发布就绪包 |

## 触发场景

本 Skill 可处理以下六种场景，AI 会根据用户输入自动匹配：

| 场景 | 用户可能说 | 触发流程 |
|------|-----------|---------|
| 启动新书 | "开新书""新建小说""想写一个..." | 立项 → 世界观 → 大纲 |
| 日常更新 | "写下一章""今天的更新""续写" | 快速循环 |
| 质量检查 | "审核这章""帮我看看这段" | 审核流程 |
| 剧情诊断 | "卡文了""写不下去了""这里有问题" | 诊断 + 角色匹配解决方案 |
| 团队管理 | "分配任务""查看进度""成员管理" | 管理模式 |
| 市场分析 | "什么题材火""数据分析""市场趋势" | 市场分析简报 |

## 快速开始

### 启动新书

```
用户: 我想写一本玄幻小说
AI: 请提供一句话梗概或核心创意
用户: 一个现代杀手穿越到修仙世界，发现这里的功法可以用杀意修炼...
AI: 【当前角色：Chief - 主编】
     输出 2-3 个方向建议供用户选择...
```

### 日常更新

```
用户: 写下一章
AI: 【当前角色：Architect - 总策划】
     确认当前进度，检查待处理审核意见...
     进入快速循环...
```

### 质量检查

```
用户: 审核这章
AI: 【当前角色：Reviewer - 审核编辑】
     输出《审核意见书》...
```

## 质量门控

五个关键门控点，每个阶段产出必须通过才能进入下一阶段：

| 门控点 | 检查角色 | 一票否决项 |
|--------|---------|-----------|
| 大纲审批 | `[Chief]` | 没有明确的主线目标 |
| 章纲卡 | `[Architect]` | 无结尾钩子 |
| 正文质量 | `[Reviewer]` | 主角超 2 章无主动行为 |
| 一致性 | `[Spotter]` | 出现吃设定/等级混乱 |
| 终审 | `[Chief]` | P0 问题未修复 |

详见 `references/quality-gates.md`。

## 男频题材模板

内置四类男频热门题材模板，详见 SKILL.md：

- **玄幻升级流** — 练气→筑基→金丹→元婴→化神→渡劫→大乘
- **都市异能** — 扮猪吃老虎、财富积累、权力博弈
- **历史架空** — 知识降维打击、权谋布局、科技攀爬
- **系统流/赘婿文** — 系统奖励、任务机制、反转打脸

## 安装

### 通过 npx skills 安装（推荐）

```bash
npx skills add https://github.com/laingyulee/web-novel-studio-skill --skill web-novel-studio
```

也可直接把这段话发给有 shell 权限的 AI Agent：

```text
帮我安装 web-novel-studio。请把 https://github.com/laingyulee/web-novel-studio-skill 克隆到技能目录，安装完成后检查 SKILL.md、references/、evals/ 是否存在。
```

### 手动安装

将 `web-novel-studio` 目录复制到 opencode 技能目录下：

```bash
# 默认技能目录
cp -r web-novel-studio ~/.agent/skills/
```
