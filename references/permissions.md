# 权限矩阵 (Permission Matrix)

## 权限级别定义

| 级别 | 含义 | 标识 |
|------|------|------|
| ✅ 执行 | 可以独立执行此操作 | E |
| 🔍 建议 | 可以提建议但需上级审批 | S |
| 🚫 无权 | 不可操作此事项 | N |
| 👑 决策 | 拥有最终决定权 | D |

## 按场景的权限规则

### 新书立项场景
```
用户提供创意
  → [Architect] 可建议方向 (E)
  → [Chief] 决策方向 (D)
  → [Architect] 写立项书 (E)
  → [Chief] 审批立项书 (D)
```

### 日常更新场景
```
[Chief] 确认当前需要更新 (D)
  → [Architect] 准备章纲 (E)
  → [Writer] 写正文 (E)
  → [Reviewer] 审核 (E)
    → P0 存在 → 退回 [Writer] 修改
    → 无 P0   → 进入下一步
  → [Polisher] 润色 (E)
  → [Spotter] 一致性检查 (E)
  → [Chief] 终审 (D)
    → 通过 → [Editor] 发布包 (E)
    → 退回 → 退回对应角色
```

### 争议裁决场景
当出现以下争议时，`[Chief]` 拥有最终裁决权：

| 争议类型 | 双方 | 首席裁决原则 |
|---------|------|-------------|
| 审核 vs 执笔 | Reviewer 认为需改，Writer 认为不用 | 以读者体验为最高标准 |
| 作者 vs 编辑 | 作者想写 A，编辑建议写 B | 以数据和市场表现为参考 |
| 设定变更 | Architect 想改设定，Spotter 认为会矛盾 | 改后必须全局检查一致性 |

## 角色责任连带规则

各角色对其产出物的质量承担连带责任：

1. **Writer** 对正文质量负责 — 如果因正文质量问题导致退回，Writer 优先修改
2. **Reviewer** 对审核漏检负责 — 如果 P0 问题在终审才被发现，Reviewer 需要复盘
3. **Spotter** 对设定一致性负责 — 如果出现吃设定且未被标记，Spotter 承担责任
4. **Polisher** 对文风统一负责 — 如果同一章内风格跳跃，Polisher 承担责任
5. **Chief** 对最终产出负责 — 终审通过的章节质量问题，Chief 承担管理责任

## 团队管理模式下的权限

当用于管理人类团队时，权限映射关系：

| 人类团队角色 | 对应 Skill 角色 | 权限范围 |
|-------------|----------------|---------|
| 签约作者 | `[Writer]` | 写作、修改自己的章节 |
| 资深作者 | `[Writer]` + `[Spotter]` | 写作 + 参与一致性检查 |
| 编辑 | `[Reviewer]` + `[Editor]` | 审核 + 运营管理 |
| 主编 | `[Chief]` | 全部权限 |

### 团队任务分配规则
1. **按擅长题材分配** — 擅长玄幻的写玄幻卷，擅长都市的写都市卷
2. **负载均衡** — 优先分配给当前负载率最低的可用成员
3. **质量优先** — 审核退回率 > 20% 的作者减少分配量
4. **新人保护** — 新人作者前 3 章必须有资深审核保驾
