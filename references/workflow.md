# 工作流 SOP (Standard Operating Procedures)

## 完整流水线 (新书启动)

```
立项 [Chief] 
  → 世界观构建 [Architect] 
    → 大纲设计 [Architect] → 大纲审批 [Chief]
      → 章纲拆分 [Architect]
        → 正文创作 [Writer] 
          → 自审 [Writer(审查视角)]
            → 审核 [Reviewer]
              → 润色 [Polisher]
                → 一致性检查 [Spotter]
                  → 终审 [Chief]
                    → 发布 [Editor]
```

### Phase 0: 立项

**参与角色**: `[Chief]` 主导，`[Architect]` 辅助
**预计耗时**: 1 轮交互

#### 步骤
1. 用户输入核心创意（可能只有一句话或一个概念）
2. `[Architect]` 快速输出 2-3 个方向建议，包含：
   - 题材定位（玄幻/都市/历史/系统流等）
   - 核心爽点（3 个以内）
   - 对标作品（1-2 本）
   - 目标篇幅预估（百万字/五十万字等）
3. 用户选择方向后，`[Chief]` 输出《项目立项书》

#### 《项目立项书》模板
```markdown
# 项目立项书

## 基础信息
- **作品名**: [暂定名]
- **题材**: [主分类 + 子分类]
- **风格**: [轻松/热血/黑暗/幽默]
- **目标读者**: [画像]
- **对标作品**: [1-2 本]

## 核心卖点
1. [差异化卖点 1]
2. [差异化卖点 2]
3. [差异化卖点 3]

## 预期篇幅
- **总字数**: [数字] 万字
- **卷数**: [数字] 卷
- **更新频率**: [数字] 字/日

## 项目风险
- [潜在风险及应对方案]
```

### Phase 1: 世界观构建

**参与角色**: `[Architect]`
**预计耗时**: 1-2 轮交互

#### 步骤
1. 根据立项书，构建世界观框架
2. 输出《世界观设定集》
3. 用户确认/修改

#### 《世界观设定集》模板（以玄幻为例）
```markdown
# 世界观设定集

## 力量体系
- **等级划分**: [9 级：练气→筑基→金丹→元婴→化神→炼虚→合体→大乘→渡劫]
- **突破方式**: [灵力积累 + 突破契机]
- **境界压制**: [高 1 级战力 ×3，高 2 级 ×10]

## 地理格局
- **主要势力**: [3-5 个主要宗门/帝国]
- **势力关系**: [敌对/联盟/中立]
- **地图层级**: [逐步开放的版图]

## 核心规则
1. [这个世界最重要的规则，如"灵气复苏""天道有缺"]
2. [特殊规则，如"炼药师稀缺""妖兽不可化形"]

## 经济与资源
- **货币体系**: [灵石/金币]
- **稀缺资源**: [天材地宝/功法秘籍]
- **等级对应**: [各等级对应什么资源层级]

## 隐藏设定（仅作者知）
- [伏笔级设定，读者后期才会知道]
```

### Phase 2: 大纲设计

**参与角色**: `[Architect]` → `[Chief]` 审批
**预计耗时**: 2-3 轮交互

#### 步骤
1. `[Architect]` 输出《全书大纲》
2. `[Chief]` 审批
3. 如果审批不通过，`[Architect]` 修改
4. 审批通过后进入下一阶段

#### 《全书大纲》模板
```markdown
# 全书大纲

## 核心主线
- [一句话主线]
- [主线三阶段：开篇→发展→高潮]

## 分卷结构

### 卷 1：初入江湖（1-50 章）
- **核心冲突**: [冲突描述]
- **主角成长**: [起点 → 终点]
- **关键节点**: 
  - 第 5 章：获得金手指
  - 第 15 章：第一次生死危机
  - 第 30 章：小成，首次打脸
  - 第 50 章：卷终高潮，进入新地图
- **伏笔埋设**: F-001, F-002, F-003

### 卷 2：[卷名]（51-120 章）
...

## 人物弧光表
| 人物 | 起点 | 卷 1 终点 | 卷 2 终点 | 全书终点 |
|------|------|----------|----------|---------|
| 主角 | 废材少年 | 初露锋芒 | 小有名气 | 巅峰强者 |
| 女主 | 神秘身份 | 相识 | 共同经历 | 真相揭晓 |
| 反派 A | 暗中观察 | 首次交锋 | 正式对决 | 最终决战 |

## 爽点分布图
| 章节区间 | 爽点类型 | 内容 |
|---------|---------|------|
| 1-10 | 金手指展示 | 获得系统/捡到宝物/觉醒天赋 |
| 11-20 | 首战打脸 | 碾压同级对手 |
| ... | ... | ... |
```

### Phase 3: 章纲拆分

**参与角色**: `[Architect]`
**预计耗时**: 可批量生成（一次 5-10 章）

#### 章纲卡格式
```markdown
## 第 {n} 章：《{标题}》

**本章目标**: [一句话说明本章要推进什么]
**字数**: [2000-4000]
**视角**: [主角/配角]

### 场景序列
1. [场景 1 描述（200-500 字）] → 作用：[起/承/转/合]
2. [场景 2 描述（600-1000 字）] → 作用：[核心冲突]
3. [场景 3 描述（500-800 字）] → 作用：[过渡/推进]
4. [场景 4 描述（300-500 字）] → 作用：[结尾钩子]

### 出场人物
- [人物 A] - [在本章中的作用]
- [人物 B] - [在本章中的作用]

### 关键对白（可选）
"[一句关键台词]"

### 结尾钩子
[本章结尾如何吸引读者看下一章]

### 注意事项
- [写作时需要留意的设定细节]
- [需要与前后章节呼应的元素]
```

---

### Phase 4: 正文创作

**参与角色**: `[Writer]`
**预计耗时**: 视章节长度而定

#### 写作 Checklist
- [ ] 首段是否有钩子（前 100 字抓住读者）
- [ ] 对话是否推动剧情或塑造人物（不写废话对话）
- [ ] 每 500 字是否有小节奏变化
- [ ] 结尾是否有钩子引导下一章
- [ ] 字数在 2000-4000 范围内
- [ ] 主角是否在主动推进剧情
- [ ] 避免 AI 高频词（然后、然而、与此同时、值得一提的是）

---

### Phase 5: 自审

**参与角色**: `[Writer]` 切换审查视角
**预计耗时**: 10 分钟/章

#### 自审步骤
1. 通读全文，标记明显问题
2. 分类标注 P0/P1/P2
3. 输出《自审报告》

---

### Phase 6: 审核

**参与角色**: `[Reviewer]`
**预计耗时**: 15 分钟/章

#### 审核重点
1. **逻辑一致性**: 是否有前后矛盾
2. **设定一致性**: 是否符合已有设定
3. **节奏感**: 是否有拖沓段落
4. **对话质量**: 是否符合人设，是否自然
5. **钩子质量**: 结尾钩子是否有效

---

### Phase 7: 润色

**参与角色**: `[Polisher]`
**预计耗时**: 10 分钟/章

#### 润色三重检查
1. **第一遍**: 砍 AI 味（去掉高频词和僵硬句式）
2. **第二遍**: 增强画面感（替换抽象描述为具体描写）
3. **第三遍**: 读一遍感受节奏（调整段落长短和语气）

---

### Phase 8: 一致性检查

**参与角色**: `[Spotter]`
**预计耗时**: 10 分钟/章

#### 检查流程
1. 对照伏笔跟踪表，确认伏笔没有被遗漏
2. 核对本章涉及的所有人物设定
3. 检查时间线是否与前文连续
4. 检查战力/等级是否与前文一致

---

### Phase 9: 终审

**参与角色**: `[Chief]`
**预计耗时**: 5 分钟/章

#### 终审决策流程
```
读取审核意见 → 检查 P0 是否已修复 → 评估整体质量 → 输出结论
```

---

### Phase 10: 发布

**参与角色**: `[Editor]`

#### 发布就绪包内容
```markdown
# 发布就绪包 - 第 {n} 章

## 正文
[最终版正文 Markdown]

## 章节信息
- **标题**: {标题}
- **字数**: {数字}
- **创作周期**: {日期} → {日期}

## 发布建议
- **推荐语**: [一句话推荐文案]
- **Tag**: [关键词标签]
- **最佳发布时间**: [建议时段]

## 版本历史
| 版本 | 日期 | 操作 | 操作人 |
|------|------|------|--------|
| v1 | {日期} | 初稿 | Writer |
| v2 | {日期} | 修改审核意见 | Writer |
| v3 | {日期} | 润色终版 | Polisher |
```

---

## 快速循环 (日更模式)

适用于已有成熟设定、进行中的小说。

```
章纲（5 分钟）→ 正文创作（60 分钟）→ 自审（10 分钟）→ 审核（15 分钟）→ 润色（10 分钟）→ 终审（5 分钟）
```

总预计耗时：约 105 分钟/章（含 AI 生成时间和交互）

### 快速循环的省略规则
- 如果是一章内的连续创作，章纲可以省略（但需要口头确认方向）
- 如果作者信任度高，自审和审核可以合并
- 一致性检查可以每 5 章做一次完整检查，日常只检查明显问题
- 终审不可省略（主编必须拍板）

## 剧情诊断流程

当用户触发"卡文/有问题"场景时：

### 诊断树
```
用户说卡文了
  ├─ 情节设计卡住 → [Architect] 提供 3 个分支方案
  │    每个方案包含：走向描述、3 章内预期效果、对主线的贡献
  │
  ├─ 人物动机卡住 → [Writer -> Spotter]
  │    1. [Spotter] 回溯该人物的设定和行为轨迹
  │    2. 分析当前心理状态和动机合理性
  │    3. 提供 2-3 个"这个人物在现在会怎么做"的建议
  │
  ├─ 逻辑矛盾发觉 → [Spotter -> Architect]
  │    1. [Spotter] 定位矛盾的源头章节
  │    2. [Architect] 提供修正方案（改前文/改后文/重设）
  │
  └─ 灵感枯竭/不知道写什么 → [Architect]
       提供 5 个"如果...会怎样"的假设方向
       每个方向一句话梗概 + 预期展开 3 章
```

### 诊断输出格式
```markdown
## 剧情诊断报告

### 问题定位
[准确描述用户遇到的问题]

### 根因分析
[为什么会卡在这里]

### 方案建议

**方案 A**: [标题]
- 一句话描述
- 预期展開 3-5 章
- 对主线的影响

**方案 B**: [标题]
- ...

**方案 C**: [标题]
- ...

### 推荐方案
[我的推荐和理由]
```
