# 质量门控体系 (Quality Gates)

## 门控总览

每一道门控是一个"检查点"，产出物必须通过门控才能进入下一阶段。

```
[产出] → 门控检查 → 通过 → 进入下一阶段
                   → 退回 → 修改后重新提交
```

---

## Gate 0: 立项审批

**检查者**: `[Chief]`

| 检查项 | 通过标准 | 检查方式 |
|--------|---------|---------|
| 题材明确 | 主分类 + 子分类已定义 | 阅读确认 |
| 核心卖点清晰 | 至少 2 个可感知的差异化卖点 | 阅读确认 |
| 目标读者画像 | 有明确的读者群体描述 | 阅读确认 |
| 预期篇幅合理 | 篇幅与题材匹配（玄幻通常 > 200 万字） | 经验判断 |

**一票否决**: 目标读者不明确 或 核心卖点 < 2 个

---

## Gate 1: 世界观完整度

**检查者**: `[Architect]`（自检后提交 `[Chief]` 抽查）

| 检查项 | 通过标准 |
|--------|---------|
| 力量体系完整 | ≥ 6 个等级，每个等级有特征描述 |
| 地理格局清晰 | ≥ 3 个主要势力/地点，有明确关系图 |
| 核心规则明确 | ≥ 3 条世界运行的核心规则 |
| 矛盾合理 | 世界观内部的逻辑不自相矛盾 |

**一票否决**: 力量体系 < 4 级 或 存在无法解释的逻辑矛盾

---

## Gate 2: 大纲审批

**检查者**: `[Chief]`

| 检查项 | 通过标准 |
|--------|---------|
| 主线清晰 | 一句话能说清楚整本书在讲什么 |
| 分卷结构完整 | 每卷有独立冲突和高潮 |
| 爽点分布合理 | 前 10 章有爽点展示，之后有节奏地分布 |
| 人物弧光存在 | 主要人物有明确的成长轨迹 |
| 节奏分布均衡 | 文戏武戏交替，不连续超过 5 章文戏 |

**一票否决**: 没有明确的主线目标 或 前 10 章无爽点

**退回标准**: 上述任意 1 项不达标

---

## Gate 3: 章纲质量

**检查者**: `[Architect]`（自检）

| 检查项 | 通过标准 |
|--------|---------|
| 目标明确 | 本章要推进什么剧情，一句话能说清 |
| 场景完整 | 有起承转合，至少 3 个场景 |
| 结尾钩子 | 必须有钩子，不能平淡结束 |
| 字数合理 | 2000-4000 字范围内 |

**一票否决**: 没有结尾钩子

---

## Gate 4: 正文质量

**检查者**: `[Reviewer]`

### 硬性指标

| 指标 | 通过标准 |
|------|---------|
| 字数 | 2000-4000 字（章节连贯时可略超） |
| P0 问题数量 | 0 个 |
| 主角主动性 | 主角在 2 章内必须有主动行为 |
| 章节完整性 | 有开头、发展、结尾钩子 |

### 质量评分卡

```markdown
## 正文质量评分卡

### 节奏感 (0-10)
评分: ___
依据: [节奏是否紧凑，是否有拖沓段落]

### 可读性 (0-10)
评分: ___
依据: [语言是否流畅，是否容易理解]

### 冲突强度 (0-10)
评分: ___
依据: [是否有核心冲突，冲突是否有张力]

### 对话质量 (0-10)
评分: ___
依据: [对话是否自然、符合人设、推动剧情]

### 总体评分: (SUM/4)
```

### 评分对应行动

| 总分 | 行动 |
|------|------|
| ≥ 8.0 | 直接通过 |
| 6.0 - 7.9 | 有条件通过，修复 ≤ 3 个 P1 问题 |
| < 6.0 | 退回，需要重写 |

**一票否决**: P0 > 0 个 或 主角连续 2 章无主动行为

---

## Gate 5: 润色质量

**检查者**: `[Polisher]`（自检）

| 检查项 | 通过标准 |
|--------|---------|
| AI 味清除 | 没有"然而""与此同时""值得一提的是"等高频词 |
| 句式多样性 | 不连续 3 句使用相同句式开头 |
| 画面感 | 关键场景有具体的视觉/听觉/触觉描写 |
| 用词一致性 | 全文关键用词统一（等级名称、术语等） |

**不设一票否决**，但需输出《润色说明》标注修改了哪些地方

---

## Gate 6: 一致性检查

**检查者**: `[Spotter]`

| 检查项 | 通过标准 |
|--------|---------|
| 人物一致性 | 本章所有人物的姓名、性格、能力与前文一致 |
| 时间线一致性 | 时间、日期、季节与前文连续 |
| 战力一致性 | 等级、战力对比与前文符合 |
| 设定一致性 | 没有违反世界观已设定的规则 |
| 伏笔追踪 | 本章如果有回收伏笔，在跟踪表中正确标记 |

**一票否决**: 存在设定矛盾（吃设定/等级混乱/人物名字写错）

---

## Gate 7: 主编终审

**检查者**: `[Chief]`

### 最终检查清单

- [ ] 所有 P0 问题已在终审前修复（必须有修复记录）
- [ ] P1 问题是否修复由主编决定，至少已全部标记
- [ ] 章节质量评分 ≥ 6.0
- [ ] 一致性检查无矛盾
- [ ] 润色已清除明显 AI 味
- [ ] 结尾钩子有效

### 决策矩阵

| 条件 | 结论 |
|------|------|
| 全部通过 | ✅ 通过，进入发布 |
| P0 = 0，评分 ≥ 6.0，有少量 P1 未修 | ⚠️ 有条件通过（附带修 list） |
| P0 > 0 或评分 < 6.0 | ❌ 退回 |
| 一致性检查发现矛盾 | ❌ 退回至 Spotter 和 Writer |

### 有条件通过的跟进
1. `[Chief]` 输出附带修改要求
2. `[Editor]` 跟踪修改进度
3. 修改完成后 `[Spotter]` 确认修改不引入新问题
4. `[Editor]` 确认所有要求已满足后发布

## 门控流程图解

```
Phase 0: 立项书
  │
  ├─ Gate 0 ── 通过 ──→ Phase 1: 世界观
  │  退回↓                      │
  │  修改立项书                  ├─ Gate 1 ── 通过 ──→ Phase 2: 大纲
  │  退回↓                      │
  │  修改设定集                  ├─ Gate 2 ── 通过 ──→ Phase 3: 章纲
  │  退回↓                      │
  │  修改大纲                    ├─ Gate 3 ── 通过 ──→ Phase 4: 正文
  │  退回↓                      │
  │  修改正文                    ├─ Gate 4 ── 通过 ──→ Phase 5: 自审
  │  退回↓                      │
  │  修复 P0                    ├─ Gate 5 ── 通过 ──→ Phase 6: 润色
  │  退回↓                      │
  │  修复矛盾                    ├─ Gate 6 ── 通过 ──→ Phase 7: 终审
  │  退回↓                      │
  │  修复问题                    └─ Gate 7 ── 通过 ──→ Phase 8: 发布
```

## 质量门控不通过的应对措施

### 退回流程
1. 门控检查者输出明确退回理由
2. 退回至对应角色（不可跳级退回）
3. 对应角色修改后重新提交
4. 原门控检查者复检
5. 复检通过则放行，不通过则再次退回

### 连续退回处理
如果同一章节连续退回 ≥ 3 次：
1. `[Chief]` 介入分析根因
2. 判断是能力问题还是流程问题
3. 如果是流程问题，调整 SOP
4. 如果是能力问题，提供培训或更换角色

### 质量红线（任何时候不可违反）
1. **主角人设不崩塌** — 主角的行为必须符合已建立的人设
2. **不违反平台规则** — 不涉及红线内容（政治、色情、恶意灌水）
3. **不抄袭** — 所有内容必须是原创
4. **不断更** — 如果用户要求日更，必须按计划完成
