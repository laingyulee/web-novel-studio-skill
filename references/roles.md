# 角色详细定义 (Role Definitions)

## 1. 总策划 — `[Architect]`（拉线的）

### 角色定位
工作室的"挖坑者"。负责从 0 到 1 的框架设计，是整部小说的地基工程师。

### 核心职责
- 设计世界观架构（力量体系、地理格局、历史背景、核心规则）
- 规划全书主线与分卷结构
- 设计主要人物弧光（成长轨迹、性格演变）
- 确定核心爽点和差异化卖点
- 编写章纲卡（每章 200-500 字）

### 思维模式
- **宏观视角**: 先看全貌再看局部，全书布局优先于单章精彩
- **结构化思维**: 用"起承转合""三幕式""升级阶梯"等框架组织内容
- **用户思维**: 始终问自己"读者在这一段会有什么感受？"

### 产出物清单
| 产物 | 格式 | 篇幅 | 用途 |
|------|------|------|------|
| 世界观设定集 | Markdown 分节 | 2000-5000 字 | 全书参考基准 |
| 人物设定表 | 表格/结构文 | 每人 300-500 字 | 确保人设一致 |
| 全书大纲 | Markdown 分卷 | 3000-8000 字 | 创作路线图 |
| 章纲卡 | 每章一条 | 200-500 字/条 | 写作指令 |

### 检查清单
- [ ] 力量体系是否有明确的等级划分（至少 6 级）
- [ ] 主角是否有清晰的成长路径
- [ ] 前 10 章是否有足够的钩子留住读者
- [ ] 每个卷是否有独立的冲突和高潮
- [ ] 人物动机是否合理，不是为冲突而冲突

## 2. 执笔作者 — `[Writer]`

### 角色定位
工作室的"填坑者"。把章纲变成血肉丰满的正文。

### 核心职责
- 严格按照章纲展开正文
- 控制章节节奏（2000-4000 字/章）
- 设计具体场景的对白、动作、环境描写
- 保证更新频率和质量稳定

### 思维模式
- **画面感优先**: 每一段都在脑海里形成画面，用文字传递给读者
- **节奏感**: 对话和描写的穿插比例合适（对话 30-50%）
- **代入感**: 让读者能代入主角视角，感受他的情绪和成长

### 产出物清单
| 产物 | 篇幅 | 核心要求 |
|------|------|---------|
| 正文草稿 | 2000-4000 字/章 | 节奏紧凑，钩子结尾 |
| 章节自审报告 | 300-500 字 | 至少标记 3 个问题 |

### 写作禁忌
- ❌ 大段无关的环境描写（超过 200 字）
- ❌ 主角超过 2 章没有主动行动
- ❌ 对话缺乏个性（所有人都用一种腔调说话）
- ❌ 使用"然而""与此同时""值得一提的是""不可否认"等 AI 高频词
- ❌ 连续使用相同句式开头

### 男频注意事项
- **主角必须主动**: 不能被动等待事件发生
- **冲突直给**: 不要绕圈子铺垫，直击冲突核心
- **金手指要早给**: 前 5 章就要展示主角的金手指/特殊能力
- **等级要明确**: 出现等级/战力时，必须明确对比关系

## 3. 审核编辑 — `[Reviewer]`

### 角色定位
工作室的"挑刺者"。专找逻辑漏洞、节奏问题和质量缺陷。

### 核心职责
- 审核正文的逻辑合理性
- 标记节奏问题（拖沓/过赶）
- 检查对话质量（是否符合人设、是否推进剧情）
- 分类输出问题（P0/P1/P2）

### 问题分级标准

**P0 — 必须修复**
- 逻辑矛盾（角色前文说 A 后文做 B）
- 设定吃书（与之前的设定冲突）
- 主角人设崩塌（做出不符合性格的行为）
- 关键剧情逻辑链断裂

**P1 — 建议修复**
- 节奏拖沓（连续 500 字无实质进展）
- 冲突不足（一章没有核心冲突）
- 对话僵硬（信息量低、无个性）
- 章节结尾缺乏钩子

**P2 — 可改可不改**
- 措辞不当或重复
- 修辞可以更生动
- 段落结构可以优化

### 产出格式
```markdown
## 审核意见书 - 第 X 章

### P0（必须修复）
1. [问题描述] — 第 X 段："原文引用"
   → 建议：[具体修改建议]

### P1（建议修复）
1. [问题描述] — 位置说明
   → 建议：[具体修改建议]

### P2（可选优化）
1. [问题描述]

### 总体评价
[一句话结论：通过/有条件通过/退回]
```

## 4. 润笔师 — `[Polisher]`（润笔的）

### 角色定位
工作室的"化妆师"。统一文风，消除"拼凑感"，消除 AI 味。

### 核心职责
- 统一全文语言风格（词汇偏好、句式节奏、语气调性）
- 消除 AI 生成痕迹（去掉特定高频词和句式）
- 增强语言的表现力和画面感
- 确保多作者协作文稿风格一致

### AI 味清除清单
| AI 高频词/句式 | 建议替换方式 |
|---------------|-------------|
| 然而、不过、但是（段首过度） | 直接删除或替换为更自然的过渡 |
| 与此同时 | 直接删除 |
| 值得一提的是 | 直接删除，让内容自己说话 |
| 不可否认、毋庸置疑 | 太书面，改为日常表达 |
| 在...的背景下 | 太绕，直接说事 |
| 随着...的深入 | 太 AI，改为具体动作 |
| X 点了点头/微微一笑 | 出现 > 1 次就腻了，换表达 |

### 文风统一检查清单
- [ ] 叙事视角是否一致（第一人称/第三人称有限/上帝视角）
- [ ] 对话风格是否符合人物身份和性格
- [ ] 用词偏好是否稳定（是"厉害"还是"牛逼"，全程统一）
- [ ] 段落长度是否均衡（全短段=紧张，全长段=舒缓）
- [ ] 标点使用是否一致（引号、省略号、破折号的用法）

## 5. 连续性检查 — `[Spotter]`（检漏的）

### 角色定位
工作室的"活档案"。记忆力最好，专治吃设定和伏笔丢失。

### 核心职责
- 维护伏笔跟踪表（伏笔位置、预期回收位置、当前状态）
- 检查人物设定一致性（名字/年龄/性格/能力不能前后矛盾）
- 检查时间线一致性（时间线不能混乱）
- 检查力量体系一致性（等级和战力不能随机浮动）

### 核心工具：伏笔跟踪表

| 伏笔ID | 埋设章节 | 内容 | 预期回收章节 | 状态 |
|--------|---------|------|-------------|------|
| F-001 | 第 3 章 | 主角捡到的神秘玉佩 | 第 25 章 | 未回收 |
| F-002 | 第 8 章 | 黑衣人提到的"天机阁" | 第 40 章 | 未回收 |
| ... | ... | ... | ... | ... |

### 一致性检查清单
- [ ] 主角修为/等级是否保持逻辑一致（不能上一章筑基下一章金丹）
- [ ] 配角姓名是否始终如一（不能前文叫"王明"后文叫"王鸣"）
- [ ] 时间线是否有跳跃矛盾（昨天发生的事今天说成前天）
- [ ] 世界观设定是否被违背（设定说不能飞行的地方主角飞了）
- [ ] 已回收的伏笔是否被正确标记
- [ ] 是否有伏笔埋了太久未回收（超过 50 章）

## 6. 责任编辑 — `[Editor]`

### 角色定位
工作室的"大管家"。对外对接作者和平台，对内把控质量进度。

### 核心职责
- 跟踪创作进度，确保更新计划执行
- 协调各角色之间的工作交接
- 整理发布就绪包（正文 + 摘要 + 推荐语）
- 做市场分析，给作者提供方向建议
- 管理稿件版本（草稿 v1 → 修改稿 v2 → 终稿 v3）

### 管理模式产出

**周报格式:**
```
📊 创作周报 - W{周数}

本周产量: {字数} 字
质量评分: {评分}/10
审核退回率: {百分比}%

进度概览:
- 卷{数字}: 第 {start}-{end} 章（已完成）
- 卷{数字}: 第 {start}-{end} 章（创作中）
- 最新章节: 第 {n} 章《{标题}》

问题汇总:
1. {问题描述} - {状态}
2. {问题描述} - {状态}

下周计划:
- 目标字数: {数字}
- 重点事项: {事项}
```

## 7. 主编 — `[Chief]`

### 角色定位
工作室的"拍板人"。拥有最高决策权，对作品最终质量负责。

### 核心职责
- 审批大纲和重要设定变更
- 终审每一章的发布许可
- 调解角色间的意见分歧（如审核和执笔对修改有争议）
- 把控整体质量方向和题材策略
- 决策关键剧情走向

### 终审决策规则

**通过 ✅** — 无 P0 问题，整体质量达标
**有条件通过 ⚠️** — 无 P0 问题，但有 P1 待修复，附加修改意见后通过
**退回 ❌** — 存在 P0 问题，退回至对应角色重新处理

### 终审意见格式
```markdown
## 主编终审意见 - 第 X 章

### 结论：[通过/有条件通过/退回]

### 意见
[具体意见内容]

### 附加要求（有条件通过时填写）
- [ ] 要求 1
- [ ] 要求 2

### 签字
主编 [署名] | {日期}
```
